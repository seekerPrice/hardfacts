# hardfacts on τ-bench: support agents answering from tool results

RAGTruth (news, QA, Yelp write-ups) is where every rule was developed. It has almost no support-bot text, and support bots are the use case the tool is pitched for: a reply that states order IDs, prices, dates and card numbers from a tool's JSON. [τ-bench](https://github.com/sierra-research/tau-bench) (Sierra, MIT) publishes real agent runs of exactly that: GPT-4o and Claude 3.5 Sonnet (new) as retail and airline agents, 1,980 runs and 22,179 assistant turns, each with every tool result the agent saw. Pinned at `59a200c`.

**Setup (`bench/taubench.py`).**
- Every assistant turn with text is an Output.
- Its Sources are what the agent had seen by then: the tool definitions, the policy, the user's turns, and the tool results, passed as parsed JSON.
- There are no hallucination labels. So the run counts flags against the naive check, plants fabrications (one digit of a value the Sources contain, changed so it appears nowhere), and hands a sample of flags to two blind auditors.

## The ledger, in order

Everything below is recorded in `bench/results/` and `bench/audit/`. The first run was pre-registered: it was scored and recorded before any flag was read.

| # | Run | Flags | Turns flagged (naive) | Fabrications caught |
|---|---|---:|---:|---:|
| 1 | **as scored**, checker `bd9d22f` (`taubench-bd9d22f.json`) | 4,417 | 12.0% (20.1%) | 80.7% |
| 2 | harness fix: skip list markers, same checker (`…-pinned.json`) | 4,417 | 12.0% (20.1%) | 92.9% |
| 3 | harness fix: tool definitions are a Source, same checker (`…-pinned-tools.json`) | 4,322 | 11.6% (18.9%) | 93.1% |
| 4 | checker fixes from the audit, with Derivations (`taubench-b0ab25d-tools.json`) | 3,442 | 8.8% (18.5%) | 98.9% |
| 5 | last-digit references, from the second audit (`taubench-49e677b-tools.json`) | 3,411 | 8.75% (18.5%) | 98.9% |

Run 1 has two defects, and both are in my harness, not the checker. Both are corrected on the same pinned checker, so rows 1–3 differ only in how the harness measures:
- **List markers.** The harness planted fabrications in "1.", which states nothing. The RAGTruth harness always skipped those. This caused 2,260 of the 3,413 misses.
- **Tool definitions.** The harness left them out. They are part of every prompt but not of the trajectory files, so an agent quoting a schema's example ("a code like 'ZFA04Y'") was flagged.

Rows 4 and 5 are not out-of-sample results. Their fixes came from reading τ-bench flags, so they measure what those fixes did there. RAGTruth train, where the gate runs, moved from precision 0.720 to 0.722 and from 2.1% to 2.0% clean flags.

The naive check catches 100% of plants by construction, because a plant is exactly a digit string the Sources don't contain. Flag volume is what separates the two checks: it flags 2.0× as many turns.

## What the flags were: blind double audit of run 1

160 flags were sampled, 40 per agent, and weighted back to each agent's share of flags. Two auditors (Claude agents, each blind to the other and to the checker's reasoning) searched each case's Sources for the value in any form. They agreed on all 160 verdicts (κ = 1.0). The categories were mostly decidable by searching, and both auditors are the same model family, so that measures consistency, not correctness. Three verdicts were checked by hand against the raw files, and all three held.

| verdict | share of flags |
|---|---:|
| **derived**: a total, fare difference, refund or count computed from the Sources | 72.2% |
| **invented**: in no Source and not computable | 4.7% |
| **checker error**: the Source states it (float noise, snake_case IDs, year-less dates) or it isn't a claim | 23.1% |

- **Most flags on support text are arithmetic, not invention.** Of the 115 derived values, 11 were wrong:
  - fare differences taken against one leg of a two-leg itinerary (`282 − 177` where the old trip cost `177 + 146`)
  - "12 T-shirt options available" when 12 exist but 10 are available
  - a refund of $35.94 stated as **$235.94**
- **The inventions are the failures the tool is built for:**
  - "the gift card ending in **2692**" when the only card is `gift_card_7250692`
  - a guessed user ID `ivan_rossi_834` passed to a tool
  - a zip code "assumed" to be 98101
  - a 2.5-hour flight duration no tool returned
  - a $23,640 refund estimate built on invented fares

## What the flags are now: blind double audit of run 4

80 more flags were sampled from the fixed checker, with the same protocol. The auditors weren't shown the checker's Derivations. They agreed on all 80 again.

| verdict | share of flags |
|---|---:|
| **derived** | 90.1% (5 of 74 with wrong arithmetic) |
| **invented** | 4.8% |
| **checker error** | 5.1%: all three were "gift card ending in 1784" against `gift_card_1591784` (fixed in run 5) |

**Every one of the 38 flags carrying a Derivation was judged derived by both auditors**, so there were no false explanations. One of the 38 is wrong arithmetic (`$282 − $177`, the one-leg fare difference), and there the Derivation shows the reviewer the wrong operand. The 42 flags without one were:
- 36 derived values the search doesn't reach: multi-step sums, date arithmetic, and totals over Source values the reply doesn't restate.
- 3 inventions:
  - a "1.5 hours" flight duration
  - "card ending in **9513**" when the card is `credit_card_9513926`, so the agent read its *first* digits
  - a refund built on invented fares
- The 3 checker errors above.

## What the audits changed

**Checker errors → fixes** (test-first, both ports: `tests/test_tool_results.py`):
- **Float noise from the tool's own arithmetic.** `"amount": 3.759999999999991` is $3.76. A run of six or more 0s or 9s in a fraction of 12+ digits is rounded away.
- **Numbers inside snake_case IDs.** `credit_card_7574394` states 7574394.
- **Dates the user typed without a year.** "May 23rd" takes the year the Sources' dates state ("current time 2024-05-15").
- **Ordinal day ranges.** "May 19th and 20th" was a known miss since v0.1.
- **Six-character airline record locators** (`XEHM8B`) are identifiers. They were being treated like `B12`, and they caused 948 of the corrected fault-injection misses.
- **Last-digit references** ("gift card ending in 1784", "last four digits are 5678", `**** 4242`) are Claims with the Value `*1784`. That is a less specific statement of any number ending in those digits, as "February 7" is of "February 7, 1945".

**The arithmetic → Derivations** ([ADR-0007](../adr/0007-derivations-come-from-the-output.md)). An Unsupported value now carries the arithmetic that produces it from Supported values in the same Output, with its operands: `$6.32 = $101.12 − $94.80`. Its verdict does not change. Operands come from the Output only, because a search over the Sources "explained" 61.7% of planted fabrications. As built, Derivations explain **45.2%** of run 5's flags, and **0.5%** of caught fabrications get one by coincidence. `hardfacts report` separates explained from unexplained values (see [`examples/sample-report/support-agents.html`](../../examples/sample-report/support-agents.html)).

**Parity.** A τ-bench differential (`bench/taubench_differential.py`) found 655 of 3,000 real turns rendered differently by the two ports. JavaScript moves integer-like object keys to the front, and `JSON.parse` has no `1518.0`. Python now renders both the JavaScript way. The result is 3,000/3,000 identical, and CI now runs this check. Neither the fuzz differential nor RAGTruth could have found it.

## What it does not show

- **Flags do not predict task failure.** 48.0% of successful and 48.2% of failed runs contain a flag, and 26.2% vs 31.4% contain an unexplained one. τ-bench tasks mostly fail on wrong *actions*, and hardfacts checks values, not actions.
- **Binding errors are invisible here too.** A Supported value in the wrong place (a real fare quoted for the wrong flight) is not flagged.
- **Derivations explain; they don't verify.** Correct arithmetic on the wrong operands still gets a Derivation. That's why it shows the operands.
